## Key Findings

### System Prompt Pipeline
1. `DefaultResourceLoader` discovers `AGENTS.md` by walking from cwd to filesystem root, looking for `AGENTS.md` or `CLAUDE.md`
2. `_rebuildSystemPrompt()` in `AgentSessionRuntime` calls `buildSystemPrompt()` which assembles: SDK base prompt + tool snippets + guidelines + project context (AGENTS.md content) + skills listing + date/cwd
3. AGENTS.md is read from disk at session start and on `/reload` — NOT hot-reloaded mid-conversation
4. Sub-agent prompts (`.pi/agents/*.md`) ARE read on demand by `discoverAgents()` when `delegate` is called
5. The host process can easily expose source prompt files, but exact effective runtime prompt requires a snapshot/export from `src/cli.ts` because host is a separate process and does not own the `AgentSessionRuntime`

### Proxy Architecture
- Double-hop pattern: Browser → proxy:8080 → host:3000. Host checks for `x-loopback: 1` header
- If host receives request WITHOUT `x-loopback`, it re-forwards through proxy (ensuring auth is applied)
- `push_svg` tool bypasses proxy, posting directly to host:3000 with `x-loopback: 1`

### Security Model
- **Proxy**: Binds to `127.0.0.1` by default. If non-loopback, requires `AUTH_TOKEN` (hard exit without it)
- **Auth check**: `Authorization: Bearer <token>` on every HTTP + WS request when non-loopback
- **Host**: No auth of its own — relies on proxy + `x-loopback` header
- **Gaps identified**: No path traversal guard on `/ui/data/*`, no CSRF protection, `x-loopback` forgeable by local processes

### Security Implications for Prompt Editor
- On loopback (default): acceptable risk, same as agent having `write` tool
- On non-loopback: bearer token covers it, but write endpoint needs `x-loopback` check + file allowlist + path traversal prevention
